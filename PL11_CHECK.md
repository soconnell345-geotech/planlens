## What changed

- `planlens/document/quantities.py`
  - New pattern `_RE_LABEL_UNIT`: `(unit)` holding exactly one unit from
    `_UNIT_TABLE`, then `:` or `=`, then an optionally signed number (with
    thousands separators, decimals, exponent or fraction, the same `_NUM`
    grammar as before). The number may not be followed by `:digit` (a time),
    `/digit` (a date) or `+digit` (a station).
  - `_label_before` reads the label back from the text before the
    parenthesis. It stops at a line break, tab, two-space column gap, `: ; = |`,
    a number (the previous field's value, when a printout's fields are joined
    on one line), a word ending a sentence, or six words. Leading joiners
    ("and", "the", ...) are dropped. No label means no mention:
    `(kip): 437.0` alone is refused.
  - If a different unit follows the value ("Depth (m): 12.5 ft") the label
    form yields to the ordinary reading (12.5 ft, no label). If it is the same
    unit ("Cover (in): 3.0 in"), it is one mention covering both.
  - Priority 0 in the overlap resolution. When a label would run back into a
    value another pattern already took, the label is trimmed to the words
    after that value rather than dropped.
  - `QuantityMention` gains `label: Optional[str] = None`. `to_dict()` emits
    `"label"` only when set, so every existing serialized mention is
    byte-identical. `__str__` prefixes `label: ` when set.
- `planlens/document/DESIGN.md`: one paragraph after "What is not read" says
  the form is now read and that the corpus-B bake-off row is the
  before-measurement.
- `CHANGELOG.md`: Unreleased entry. No version change.
- `planlens/tools/` untouched. `find_quantities` passes `to_dict()` through,
  so the tool gains `label` with no change there.
